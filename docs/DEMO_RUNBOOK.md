# 《残留项》4 分钟演示 Runbook

## 启动

Windows 候选包解压后双击：

```text
RESIDUAL-DEMO.cmd
```

右上角出现 `DEMO / LOOP 2 / FORCE` 即表示演示模式已启用。演示模式只改变
跳转入口，不改变固定高光、结局规则或 AI 权限；RouterBase 不可用时仍走本地
fallback。

## 0:00–0:30：一句话和危机

操作：保持首屏，不点击 Demo 按钮。

话术：

> 《残留项》是一款玩家和存档系统互相驯化的时间循环游戏。
> 你可以读档撤销世界，但 SAVE_03 会记住你删除过什么。

指出屏幕信息：

- 02:47 到 03:00 的清除倒计时
- 每轮 4 次关键行动
- 电话、终端、抽屉三个调查区

## 0:30–1:30：第一次取舍

按顺序点击：

1. 电话与照片
2. 再次点击电话，播放阿栀录音
3. 关闭波形面板
4. 电脑与 SAVE_03
5. 选择“删除语音，解压证据”

话术：

> 证据包需要空间，但删除录音又会失去解密需要的声纹。
> 第一轮无法同时完成，这迫使玩家主动读档。

## 1:30–2:20：存档已经记住

点击顶部 `LOOP 2`。

指出：

- 存档状态从“已保存”变为“已记录”
- 幽灵波形重新出现
- 这是上一轮删除行为的确定性结果，不依赖网络或随机模型

话术：

> 世界恢复了，责任没有。SAVE_03 把被删除的数据带进了新时间线。

## 2:20–3:35：固定高光

点击顶部 `FORCE`，随后在谈判界面选择“强制覆盖”。

保持沉默，让观众看到：

1. 读取到 99%
2. 停顿
3. 倒退到 43%
4. SAVE_03 核心裂开
5. 幽灵存档“她曾经来过”出现

话术：

> AI 不能决定这个高光。模型只能在白名单里选择态度；
> 99% 倒退、核心证据和结局都由本地规则固定。

## 3:35–4:00：收束

话术：

> SAVE_03 的人格来自阿栀那些被删除的数据。
> 当存档已经记得你删除过谁，你还会再按一次覆盖吗？

如需继续完整体验，点击高光后的继续按钮，正常进入后续证据与双结局流程。

## 现场故障切换

- RouterBase 不可用：不处理，游戏自动使用本地 fallback
- Tripo 正式模型不可用：继续使用五态程序化 SAVE_03 核心
- 音频设备异常：点击顶部“静音”，照常演示视觉闭环
- 操作走错：点击 `LOOP 2` 或 `FORCE` 恢复到确定性演示节点
- Windows 包无法启动：使用同版本 Godot 4.7.1 打开项目并运行主场景

## 30–60 秒备用视频镜头

备用视频只录固定高光：

1. 从 Demo Mode 首屏开始
2. 点击 `FORCE`
3. 点击“强制覆盖”
4. 完整录下 99% 停顿、倒退和“她曾经来过”
5. 画面在幽灵存档上停留 3 秒结束

推荐成片长度 35–45 秒，不添加解释字幕，现场由讲解者口述。
